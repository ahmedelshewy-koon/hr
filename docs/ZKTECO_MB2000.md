# ربط جهاز البصمة ZKTeco MB2000

تم ربط الجهاز `192.168.1.147:4370` من خلال خدمة محلية تقرأ المستخدمين وحركات البصمة وتحفظها في نفس PostgreSQL الذي يستخدمه النظام. الشاشة موجودة في **الحضور والانصراف ← جهاز البصمة** وتتاح لمدير النظام ومدير الموارد البشرية.

## التشغيل الحالي

- اسم مهمة Windows: `Sanad HR - ZKTeco MB2000`.
- تفحص عدد المستخدمين والبصمات كل 15 ثانية دون تنزيل السجلات؛ تتم المزامنة عند تغيّر العدد أو الضغط على «مزامنة الآن». أول اتصال دون مزامنة سابقة يسحب البيانات لتهيئة خط الأساس. تعديل بيانات مستخدم دون تغيّر العدد يحتاج مزامنة يدوية.
- تبدأ عند تسجيل دخول المستخدم الحالي إلى Windows. يلزم بقاء هذا الكمبيوتر مشغلاً، ومتصلًا بشبكة الجهاز، مع تشغيل PostgreSQL. لا تعمل أثناء إغلاق الكمبيوتر أو قبل تسجيل الدخول.
- السجلات التشغيلية في `outputs/biometric-agent/` ولا تحتوي على كلمات مرور أو قوالب بصمات.
- عند تعطل الشبكة تسجل الخدمة المحاولة وتعيد المحاولة لاحقًا؛ وتعرض الشاشة آخر مزامنة ناجحة وحالة الاتصال.

لتشغيل مرة واحدة:

```powershell
npm run attendance:sync
```

لتشغيل الخدمة يدويًا:

```powershell
npm run attendance:agent
```

لإعادة تثبيت التشغيل التلقائي بعد نقل المشروع:

```powershell
powershell.exe -NoProfile -File scripts/install-biometric-agent.ps1
```

لإيقاف المهمة من Task Scheduler اختر الاسم المذكور ثم End؛ ولمنع بدء التشغيل اللاحق اختر Disable. لا يزيل ذلك السجلات المستوردة.

## طريقة احتساب الحضور

المطابقة التلقائية تستخدم `employees.fingerprint_code` مع رقم المستخدم على الجهاز؛ لا تستخدم رقم الموظف الداخلي أو تشابه الأسماء. إذا تكرر رقم البصمة بين موظفين لا يتم التخمين.

الجهاز الحالي لا يسجل اتجاه حضور/انصراف موثوقًا في كل حركة، ويُستخدم أيضًا لفتح الباب. لذلك يعرض تبويب **كل البصمات** جميع الحركات المستوردة وفق البحث والتاريخ المحددين، بينما يعرض **الحضور والانصراف** صفًا واحدًا لكل موظف في يوم العمل: أول بصمة للحضور وآخر بصمة ذات توقيت مختلف للانصراف التقديري، حتى لو كان الفرق ثانية واحدة. لا يوجد فلتر لتجميع البصمات خلال دقيقة. البصمة الواحدة، أو نسخ الحدث بنفس التوقيت تمامًا، تظل بدون انصراف. آخر بصمة تتحدث مع وصول حركات جديدة؛ ليست تأكيدًا بأن الموظف أنهى يومه. تتبع الورديات الليلية يوم بداية الوردية. التوقيت الافتراضي القاهرة ويشمل التوقيت الصيفي.

كل حركة أصلية محفوظة في `attendance_device_punches`، مع رقم المستخدم والتوقيت وحالة الجهاز الأصلية، ويمنع قيد فريد تكرارها عند إعادة السحب. حركات الموظفين المرتبطين تدخل أيضًا `attendance_logs` كمصدر `biometric`، وتُحدّث `daily_attendance` باستخدام محرك الحضور الحالي. تظل التصحيحات المعتمدة وتبريرات التأخير والانصراف المعتمدة وحالة طلبات التصحيح المعلقة محفوظة.

الأرقام التي لم ترتبط عند التنفيذ: **15، 16، 17، 29**. يمكن ربطها من تبويب **الموظفون والربط** بعد تحديد الموظف الصحيح؛ وستُحتسب بصماتها القديمة تلقائيًا. لا تنشئ الخدمة موظفين أو حسابات دخول تلقائيًا.

## التثبيت على كمبيوتر آخر

يلزم Node.js 24 أو إصدار حديث يدعم تشغيل TypeScript، و`npm ci`، و`DATABASE_URL` في متغيرات البيئة أو الملف المحلي المستبعد من Git `.dev.vars`.

```powershell
node --env-file=.dev.vars node_modules/drizzle-kit/bin.cjs migrate
npm run attendance:sync
powershell.exe -NoProfile -File scripts/install-biometric-agent.ps1
```

التطبيق المستضاف وخدمة الربط يجب أن يستخدما **نفس قاعدة البيانات**. إذا كان التطبيق خارج المكتب فلا يمكنه استخدام عنوان PostgreSQL محلي على الكمبيوتر؛ يلزم عنوان قاعدة بيانات متاح للخدمة والتطبيق معًا. لا يلزم فتح منفذ جهاز البصمة للإنترنت.

الربط يقرأ بيانات المستخدم الأساسية وحركات الحضور فقط، ولا يغير الساعة أو إعدادات الجهاز أو المستخدمين، ولا يمسح سجلات الجهاز ولا يخزن كلمات مرور مستخدميه أو قوالب الوجه أو البصمات. مكتبة الاتصال معزولة في عملية ذات مهلة زمنية، والطلبات متسلسلة على اتصال واحد. أقفال PostgreSQL تمنع تزامن عمليتي سحب لنفس الجهاز.

## التحقق

```powershell
node --test tests/biometric-attendance.test.mjs tests/attendance-corrections.test.mjs
$env:RUN_BIOMETRIC_DB_TESTS='1'
node --test tests/biometric-attendance.test.mjs
node tests/runtime-biometric-api.mjs
```

اختبار قاعدة البيانات يستخدم معاملة يتم التراجع عنها. اختبار API مخصص للتطوير المحلي ويستخدم مفتاح التوقيع المحلي دون عرضه. تمت مراجعة الاستيراد الفعلي وإعادة السحب بدون تكرار والصلاحيات والبحث وتقسيم الصفحات وزر المزامنة من المتصفح.
